# AI 协作记录

> 项目：在线投票与问卷系统
> 路线：路线 B——题库选题
> AI 工具：Codex

## 记录 1：确定项目架构和开发范围

**意图**：根据课程设计要求确定系统模块、技术栈、数据库实体和交付物，避免遗漏验收项。

**提示词**：基于 Flask + MySQL 开发在线投票与问卷系统，支持创建问卷、填写问卷、统计结果，要求单选、多选、截止时间、填写链接、防重复提交、ECharts 统计、CSV 导出，并提交源码、设计文档、开发日志、Debug 日志、AI 协作记录和 README，请给出完整实现方案。

**AI 回复摘要**：建议使用 Flask、SQLAlchemy、Jinja2、Bootstrap 和 ECharts；设计用户、问卷、题目、选项、答卷、答案等表；使用 IP 哈希和 Cookie 防重复；使用 UTF-8 BOM 导出 CSV；补充 README、ER 图和测试数据。

**我的修改/采纳**：采用 Flask + MySQL + SQLAlchemy + Jinja2 + ECharts 的方案；根据课程要求保留单选、多选和填空题；决定将测试数据脚本、运行说明和课程文档一起放入仓库。

## 记录 2：设计数据库模型

**意图**：把问卷创建、题目选项、匿名提交和统计结果转换为可实现的数据库关系。

**提示词**：请为支持单选、多选、填空的问卷系统设计 SQLAlchemy 数据模型，要求支持问卷截止、关闭、答卷、答案和多选题选项关联，并考虑删除和外键约束。

**AI 回复摘要**：建议建立 User、Survey、Question、Option、Response、Answer 六个模型；题目保存题型和必填状态；答案可以保存选项 ID 或文本；问卷与题目、答卷使用级联关系。

**我的修改/采纳**：采用六个核心模型，并增加 `public_id` 作为填写链接标识、`position` 保证题目和选项顺序、`ip_hash` 和 `visitor_token` 保存防重复标识。后续发现已有答卷编辑题目会触发外键问题，于是改为已有答卷时只修改问卷基本信息，见 DEBUG-005。

## 记录 3：实现匿名填写和防重复提交

**意图**：实现无需登录的填写端，同时满足每个填写者只能提交一次。

**提示词**：问卷填写无需登录，如何使用 IP 或简单标识限制重复提交？还要支持同一网络下多个用户分别填写，并在提交后显示感谢参与。

**AI 回复摘要**：初步建议保存 IP 哈希和随机 Cookie；进一步分析后建议登录填写者按账号区分，匿名填写者按 Cookie 区分，不要把 IP 作为唯一阻断条件；服务端仍需重新校验问卷状态、必填项和合法选项。

**我的修改/采纳**：采用 `user:<user_id>` 和 `guest:<cookie_token>` 作为问卷级填写标识，保留 IP 哈希作为审计字段。增加截止时间、关闭状态、必填校验、选项合法性校验和提交成功页面。测试发现的重复提交问题记录为 BUG-002。

## 记录 4：修复多选题必填校验

**意图**：解决多选题只能全选的问题，使必填多选题满足“至少选择一个”。

**提示词**：HTML 多选题使用多个 checkbox，当前每个 checkbox 都有 required，导致必须全选。如何改成至少选择一个，并同时保留服务端校验？

**AI 回复摘要**：不能给同一多选题的每个 checkbox 都加 `required`；应移除逐项 required，在提交前检查该题选中的数量是否大于 0，并在服务端再次判断答案列表是否为空。

**我的修改/采纳**：单选题保留 radio 的 required；多选题使用 JavaScript 按题目分组检查 `:checked`，服务端使用 `any(values)` 做最终校验。修复过程记录为 BUG-001。

## 记录 5：修复 CSV 导出错误

**意图**：解决导出 CSV 时的 500 错误，并保证 Excel 打开中文不乱码。

**提示词**：Flask CSV 导出报 `TypeError: __init__() takes 1 positional argument but 2 were given`，代码中既有 Flask Response 又有数据库 Response 模型，请定位原因并给出修复方式。

**AI 回复摘要**：数据库模型名称覆盖了 Flask 的 Response 类，应在导入时使用别名，例如 `Response as FlaskResponse`；CSV 文本前增加 UTF-8 BOM，并设置 `text/csv` 和下载文件名。

**我的修改/采纳**：将 Flask 响应类改为 `FlaskResponse`，导出时返回 `FlaskResponse('\ufeff' + csv_text, ...)`，并测试导出文件名和中文兼容性。问题记录为 BUG-003。

## 记录 6：完善多人使用和问卷编辑

**意图**：根据实际联调反馈，解决新用户看不到开放问卷，以及已有答卷编辑时的外键错误。

**提示词**：新用户登录后只能看到自己的问卷，无法看到 demo 创建的开放问卷；编辑已有答卷的问卷时删除题目选项会触发 MySQL 外键错误，请设计安全修改方案。

**AI 回复摘要**：控制面板应区分“我的问卷”和“可填写问卷”；已有答卷不能直接删除被答案引用的题目和选项，可以允许修改标题、说明、截止时间，题目结构需要版本管理或保留旧数据。

**我的修改/采纳**：增加开放问卷查询和“开始填写”入口；已有答卷时保存只更新问卷基本信息，避免破坏历史统计；没有答卷时允许完整编辑题目结构。相关问题记录为 BUG-004、BUG-005。

## 记录 7：按课程要求改进统计实现

**意图**：确保统计页不仅能显示结果，而且满足课程明确要求的 `GROUP BY + COUNT` 和多选题横向条形图。

**提示词**：当前每个选项单独调用 count，课程要求使用 SQL GROUP BY + COUNT；单选题需要柱状图/饼图，多选题需要横向条形图，请给出后端聚合查询和 ECharts 配置。

**AI 回复摘要**：使用 SQLAlchemy 的 `func.count()` 和 `group_by(Answer.option_id)` 按选项聚合；单选题使用 category + value 的纵向柱状图和饼图；多选题交换坐标轴，使用 category 的 yAxis 和 value 的 xAxis。

**我的修改/采纳**：将统计逻辑改为一次分组聚合并补齐零票选项；根据题型分别配置 ECharts。改动记录为 BUG-006、BUG-007。

## 协作复盘

本项目中 AI 主要用于方案梳理、代码骨架、报错分析、SQL 聚合思路、文档整理和验收检查。我对生成的代码进行了本地运行、页面联调和错误复现，发现问题后根据实际报错修改实现，没有直接跳过验证。后续需要继续增加自动化测试，并对问卷版本管理和多人并发场景进行独立设计与验证。

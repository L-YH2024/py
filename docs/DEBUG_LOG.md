# 在线投票与问卷系统 Debug 日志

> 每条记录按“现象 → 根因 → 解决 → 预防”整理。开发日志只引用编号，不重复展开。

## BUG-001 ｜ 2026-10-26 ｜ 多选题被浏览器要求全部选中

- **现象**：多选题只勾选一个选项后提交，浏览器提示“如果要继续，请选中此复选框”，必须把所有选项都勾上才能提交。
- **根因**：模板循环给多选题的每一个 checkbox 添加了 HTML `required` 属性。浏览器把每个复选框当作独立必填控件，因此要求每个选项都选中。
- **解决**：只给单选题的 radio 控件使用 `required`；多选题移除逐项 `required`，提交时用 JavaScript 检查同一题的 `:checked` 数量是否大于 0，服务端继续用 `any(values)` 做最终校验。
- **预防**：单选题的“必填”是必须选一个控件，多选题的“必填”是同组至少选一个，不能把两种语义直接套用同一个 HTML 属性。以后测试必填题时分别测试“全不选、选一个、全选”三种情况。

## BUG-002 ｜ 2026-10-26 ｜ 同一网络下不同填写者被误判重复

- **现象**：问卷链接被第二个用户打开后显示“请勿重复提交，同一填写者只能提交一次”，即使第二个用户实际是不同的人。
- **根因**：第一版防重复查询同时绑定了问卷、IP 哈希和 Cookie。多人使用同一电脑或同一局域网时，IP 相同，容易被当成同一填写者；同一浏览器还会继续携带原 Cookie。
- **解决**：登录填写者使用 `user:<user_id>` 作为问卷级唯一标识；匿名填写者使用 `guest:<cookie_token>`。查询重复记录时按 `survey_id + visitor_token` 判断，不再把 IP 作为阻断条件；IP 哈希仍保留用于审计。
- **预防**：防重复策略设计时先区分“账号身份”和“设备身份”，不能把 IP 当作可靠的个人身份。测试时至少使用两个账号、两个浏览器和同一局域网验证。

## BUG-003 ｜ 2026-10-26 ｜ CSV 导出出现 Response 类型错误

- **现象**：访问导出链接返回 500，报错 `TypeError: __init__() takes 1 positional argument but 2 were given`，错误指向 `return Response(...)`。
- **根因**：代码同时定义了数据库模型 `class Response(db.Model)`，又从 Flask 导入了同名响应类，后定义的数据库模型覆盖了 Flask 的 `Response` 名称。导出时调用的其实是数据库模型构造函数。
- **解决**：将 Flask 响应类改名导入为 `FlaskResponse`，CSV 导出函数使用 `FlaskResponse(...)` 返回下载响应，并保留 UTF-8 BOM `\ufeff`。
- **预防**：模型类不要使用框架常用类名；如果必须同名，应在导入时显式别名。新增导出接口后要同时测试 HTTP 状态码、下载文件名和 Excel 中文内容。

## BUG-004 ｜ 2026-10-27 ｜ 新用户看不到 demo 创建的问卷

- **现象**：新用户登录后只能看到“我的问卷”，看不到 demo 账号创建的开放问卷，无法直接进入填写。
- **根因**：控制面板最初只查询 `Survey.query.filter_by(user_id=session['user_id'])`，查询范围限定为当前创建者。
- **解决**：保留“我的问卷”查询，同时增加 `closed=False` 的开放问卷查询，新增“可填写问卷”区域和“开始填写”按钮。
- **预防**：管理视图和公共填写视图要分别设计查询范围；验收时用创建者账号、新注册账号、未登录访问链接三种身份检查可见内容。

## BUG-005 ｜ 2026-10-27 ｜ 编辑已有答卷问卷触发 MySQL 外键错误

- **现象**：编辑已有提交记录的问卷并点击保存，返回 500，MySQL 报 `IntegrityError 1451 Cannot delete or update a parent row`，因为 `answer.option_id` 仍引用被删除的选项。
- **根因**：编辑逻辑先删除旧题目，级联删除旧选项；但历史答案仍然引用这些选项，数据库外键约束禁止删除父记录。
- **解决**：编辑页面加载时提示已有答卷；如果问卷已经有答卷，保存时只更新标题、说明和截止时间，不重建题目和选项，保留历史统计。没有答卷时才允许完整修改题目结构。
- **预防**：涉及历史数据的编辑不能简单“删除后重建”。以后需要修改题目结构时，应设计问卷版本表或保留旧题目和选项 ID，再进行迁移测试。

## BUG-006 ｜ 2026-10-27 ｜ 统计实现未满足 GROUP BY + COUNT 要求

- **现象**：统计页面能显示数量，但代码对每个选项单独执行一次 `.count()`，没有形成按选项分组的聚合查询，不满足课程验收要求。
- **根因**：初版实现优先验证页面显示，采用了“遍历选项逐个计数”的写法，忽略了题目明确要求的 SQL `GROUP BY + COUNT`。
- **解决**：使用 SQLAlchemy 构造 `query(Answer.option_id, db.func.count(Answer.id)).filter(...).group_by(Answer.option_id)`，将聚合结果转换成选项 ID 到数量的映射，再补齐没有答案的选项为 0。
- **预防**：实现验收要求时先把文字要求转成检查清单；不仅验证页面结果，还要检查生成的 SQL 或 ORM 是否真正体现指定技术点。

## BUG-007 ｜ 2026-10-27 ｜ 多选题图表方向不符合要求

- **现象**：统计页的多选题使用普通纵向柱状图，课程要求的是多选题横向条形图。
- **根因**：所有单选和多选题复用了同一套 ECharts 配置，统一使用 `xAxis: category` 和 `yAxis: value`，没有按题型区分。
- **解决**：单选题继续使用纵向柱状图和饼图；多选题改为 `yAxis: category`、`xAxis: value`，数据系列使用 bar，实现横向条形图。
- **预防**：图表验收要同时检查数据、图表类型、坐标轴方向和题型映射，不能只确认页面“有图”。
